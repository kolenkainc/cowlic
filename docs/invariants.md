# Project invariants

The rules that must stay true, in one place, each with a short reason, HOW it is enforced and where its source lives. Short on purpose: the sources hold the full reasoning, this file only points to them.

- **Who reads it:** the owner, the agents (ticket-worker, pr-reviewer, project-planner) and anyone changing CI, the Worker, ingest or the agent files.
- **Purpose:** show which rules are held by structure, a test or CI, and which rest only on guidance or on a human. Rows marked **candidate** are worth a tighter control later; each is a possible follow-up ticket.
- **Enforced by:** `structure` (the code or the repository settings make the violation impossible), `test` (a named test fails), `CI` (a named job or step fails), `guidance` (written in CLAUDE.md, a doc or an agent file, nothing checks it), `human review` (the pr-reviewer or the owner). Where a row has two, both are listed.
- **Keeping it current:** a PR that adds, removes or weakens a rule, a check or a test named here updates the matching row in the same PR. A reviewer who sees a changed job, test or ruleset setting that this file cites checks the row. Citations are by file and section, job, step or test name, not by line number.
- A rule whose only source is the agents' permission policy is marked "agent permission policy outside this repository (not verifiable here)".
- No secret values, account or database ids, host names or user names belong in this file.
