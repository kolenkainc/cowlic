# Project invariants

The rules that must stay true, in one place, each with HOW it is enforced and where its source lives. Short on purpose: the sources hold the reasoning, this file only points to them.

- **Who reads it:** the owner, the agents (ticket-worker, pr-reviewer, project-planner) and anyone changing CI, the Worker, ingest or the agent files.
- **Purpose:** show which rules are held by structure, a test or CI, and which rest only on guidance or on a human. The rows marked **candidate** are the ones worth a tighter control later; each one is a possible follow-up ticket.
- **Enforced by:** `structure` (the code or the repository settings make the violation impossible), `test` (a named test fails), `CI` (a named job or step fails), `guidance` (written in CLAUDE.md or an agent file, nothing checks it), `human review` (the pr-reviewer or the owner). Where a row has two, both are listed.
- **Keeping it current:** a PR that adds, removes or weakens a rule, a check or a test named here updates the matching row in the same PR. A reviewer who sees a changed job, test or ruleset setting that this file cites checks the row. Citations are by file and section, job, step or test name, not by line number.
- No secret values, account or database ids, host names or user names belong in this file.
